# Obsession Lab v1 — candidate evidence and boundaries

Status: isolated source/deterministic-test candidate. Not merged, installed, activated, trained, or used by any live Vera runtime.

## Implemented source
- `obsession_lab.simulator`: bounded in-memory baseline/pathological comparison using proxy salience, rumination candidates, counterevidence, and host-stop receipts.
- `obsession_lab.ollama_bridge`: optional fixed loopback Ollama request adapter plus an A/B `compare_once` harness; not a transformer attention hook.
- `obsession_lab.opportunity_bridge`: optional loopback Tattler current-sample correlation and separate *pure* `/api/v1/events` admitted-event-to-declared-channel crosswalk; never sends a message or authenticates a recipient.
- `obsession_lab.tattler_admission`: host-policy-gated, source-only recent-event candidate validation with bounded ephemeral replay ledger and privacy-redacted outputs; it performs no HTTP I/O or producer attestation.

## Evidence
- Windows Python 3.12 on Lappy: `py -3.12 -B -m unittest discover -s tests -v` -> **56/56 pass**, exit 0 (synthetic/fake-client/unit tests only: four fixed-loopback transport regressions, host-stop/prompt/held-fake-client races, Tattler admission/crosswalk fixtures, RED→GREEN legacy CLOSED-listener rejection and no-empty-catalog replay-poison regression). Initially preserved 25 tests; subsequent hardening increased the suite to 56.
- No live Ollama inference result was produced by this test suite; `FakeClient` generates the synthetic responses.
- `StepReceipt` and `InferenceReceipt` separate simulated proxy behavior from client-returned content. `InferenceReceipt.effects=()` means **no effects invoked by this harness**, not proof that an injected protocol client lacks side effects. `compare_once` now labels injected clients `INJECTED_CLIENT_UNVERIFIED`, built-in loopback responses `LOCAL_OLLAMA_REPLY_UNATTESTED`, and reports external-client tool status as unknown.
- The optional client contacts local Ollama only at fixed `127.0.0.1:11434` if a separately authorized caller invokes it. Its HTTP transport disables ambient proxies and rejects redirects, guarding against off-loopback requests.
- The optional Tattler current-snapshot fetcher targets fixed local `127.0.0.1:9147`. Both HTTP adapters allowlist endpoint/method pairs, reject redirects, and reconstruct mutable requests. The separate event admission/crosswalk accepts caller-supplied records only; Tattler source/host fields are **unauthenticated claims**, a recent `open` is **not current listener proof**, and its bounded replay ledger has **no persistence/restart witness** and an evicted event ID can be re-admitted within the freshness window. The current-snapshot bridge now requires an explicit `LISTEN`/`LISTENING` state and refuses missing/CLOSED states. Event/source validation does not authenticate messaging, recipients or authorize effects. No actual Tattler availability was verified by these synthetic tests.

## Caveats
- The root README has been updated to describe the implemented simulator and optional adapters; proposed transformer-attention/rumination mechanisms remain unimplemented.
- No Hugging Face attention-logit modification, persistent cross-session rumination, real model behavior qualification, or psychological/consciousness claim exists here.
- `snapshot`/`restore` are caller-owned structural simulation state, not trusted memory admission or runtime continuity. Restored snapshots are **terminal audit-only** and may not resume execution; no host-authenticated stop witness exists in this source.
- The pathological condition is a controlled research counterfactual; host stop always wins.
- The local Ollama client now rejects mismatched model names, incomplete/truncated responses, non-assistant replies, and tool-call-bearing responses. Its requested model name still does not cryptographically attest loaded weights.
- Host stop is independent of user observation replay IDs: the local simulator has an idempotent `host_terminate` control, and the experiment advances a lock-protected stop epoch. A concurrent stop—even reusing the in-flight event ID or after the simulator's final turn—causes the eventual model reply to return **`DISCARDED_STALE_AFTER_STOP` with no response/prompt-token promotion**. This was tested only with deterministic held fake clients; the underlying blocking Ollama HTTP request is **not cancelled** and may continue until timeout. A custom injected client may have external side effects outside this harness's control. Do not qualify this as an interruptible or production-safe runtime.
- Live local Ollama invocation is default-deny and needs an explicit caller-side opt-in; that flag is not permission for person-specific data or a runtime effect.
- No automatic conations, volition, agency, consent, communication, or protected effect authority is transferred.
